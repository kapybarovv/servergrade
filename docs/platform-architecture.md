# ServerGrade Platform

Цель платформы — публичные страницы вида `servergra.de/test/12345678`, каталог
провайдеров и сравнение хостингов по одинаковой методике.

## Рекомендуемый бесплатный стек

- **Cloudflare Worker + Static Assets** — сайт, API и маршруты `/test/:id`;
- **Cloudflare D1** — тесты, хостеры, тарифы, версии методики и агрегаты;
- **Cloudflare R2** — исходные логи, PNG/SVG и JSON-пакеты результатов;
- **GitHub Actions** — линтеры, тесты и автоматический deploy;
- **GitHub** — исходный код и подписанные релизы runner-скрипта.

GitHub Pages подходит только для статического каталога. Приём результатов,
одноразовые challenge-токены и секретный ключ подписи требуют серверной части.
Vercel тоже решает задачу, но Cloudflare удобнее собирает API, SQL и объектное
хранилище в одной бесплатной инфраструктуре. Домен оплачивается отдельно.

## Поток подтверждённого теста

1. Пользователь создаёт тест на сайте и получает `test_id`, случайный `nonce`,
   срок действия и выбранный профиль тестирования.
2. Официальный runner скачивается из закреплённого release и проверяет checksum.
3. Runner выполняет полный профиль и отправляет канонический JSON, сырые логи,
   версию runner, nonce и timestamps.
4. API атомарно помечает nonce использованным, проверяет срок, схему, допустимые
   диапазоны, длительность этапов и отсутствие повторной отправки.
5. API **самостоятельно пересчитывает ServerGrade Score**. Балл клиента никогда
   не принимается как источник истины.
6. Независимые probes проверяют доступность IP, ASN, геолокацию, RTT и открытый
   контрольный endpoint. Несовпадения получают флаг `suspicious`.
7. Worker формирует хэш канонического результата и подписывает его Ed25519-ключом,
   который хранится только в Worker Secret.
8. Страница показывает статус, покрытие, версию методики, SHA-256 пакета и подпись.

## Уровни доверия

- `verified` — полный профиль, одноразовый challenge, серверный пересчёт,
  независимая сетевая проверка и валидная подпись;
- `partial` — официальный upload, но часть тестов пропущена или завершилась ошибкой;
- `unverified` — импортированный JSON/скриншот без challenge;
- `suspicious` — конфликт с probes, невозможная длительность или аномальные данные;
- `revoked` — результат отозван после изменения методики либо расследования.

Подпись гарантирует неизменность опубликованного пакета, а не физическую
честность машины. Root-владелец способен модифицировать shell-скрипт и локальный
вывод. Поэтому для рейтинга хостеров учитываются только `verified` результаты,
сетевые показатели подтверждаются внешними probes, а аномалии сравниваются с
повторными прогонами. Абсолютная защита локальных CPU/RAM/disk-метрик возможна
только с hardware attestation или доверенным агентом, чего у обычных VPS нет.

## Канонический пакет результата

```json
{
  "schema": "servergrade.result.v1",
  "test_id": "01J...",
  "challenge": { "nonce": "base64url", "issued_at": 0, "expires_at": 0 },
  "runner": { "version": "1.1.0", "sha256": "..." },
  "target": { "ip_hash": "...", "asn": 0, "country": "NL" },
  "started_at": 0,
  "finished_at": 0,
  "profile": "full-v1",
  "measurements": {},
  "evidence": [{ "name": "yabs.log", "sha256": "...", "r2_key": "..." }]
}
```

IP в публичном JSON хранится как маска или keyed hash. Полный IP, если он нужен
для probes, шифруется отдельно и удаляется по retention policy.

## Минимальная схема D1

- `providers(id, slug, name, website, disclosure)`;
- `plans(id, provider_id, region, cpu, ram_mb, disk_gb, price_monthly, currency)`;
- `tests(id, plan_id, status, methodology, score, started_at, finished_at)`;
- `category_scores(test_id, category, score, sample_count)`;
- `measurements(test_id, metric, value, unit, sample_index)`;
- `challenges(id, nonce_hash, expires_at, used_at)`;
- `artifacts(test_id, kind, r2_key, sha256)`;
- `signatures(test_id, payload_sha256, signature, key_id)`.

Индексы нужны как минимум на `tests(plan_id, status, finished_at)`,
`plans(provider_id, region)` и `challenges(nonce_hash)`.

## Справедливое сравнение хостеров

- сравнивать одинаковые ценовые корзины и регионы;
- показывать медиану, p10/p90 и число прогонов, а не только лучший результат;
- снижать вес старых тестов и явно показывать дату;
- минимум три полных прогона в разные часы для места в рейтинге;
- не учитывать тесты владельца хостинга без disclosure;
- методика и пороги версионируются, старые баллы не пересчитываются молча;
- реклама вашего хостинга визуально помечается как реклама и не влияет на балл.

## API первого релиза

- `POST /api/challenges` — создать одноразовый тест;
- `POST /api/results` — принять пакет и артефакты;
- `GET /api/tests/:id` — публичный результат и подпись;
- `GET /api/tests/:id/verify` — перепроверка хэша и подписи;
- `GET /api/providers` — каталог и агрегаты;
- `GET /api/compare?providers=a,b&region=nl&tier=10` — сравнение.

Для upload endpoints обязательны rate limit, Turnstile, лимит размера тела,
идемпотентность по `test_id` и журналирование решений верификатора.
