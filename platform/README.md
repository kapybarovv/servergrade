# Публичные страницы результатов

Cloudflare Worker публикует страницы `/test/12345678`, принимает полные метрики
runner и хранит SVG- и PNG-страницы отчёта вместе с результатом в D1.
В хедере публичного интерфейса отображается версия `v2.0`.

## Развёртывание

1. Установите Node.js, откройте этот каталог и поставьте локальный Wrangler:

   ```bash
   cd platform
   npm install
   npx wrangler login
   ```

2. Создайте бесплатную D1-базу ближе к основной аудитории:

   ```bash
   npx wrangler d1 create servergrade --location=weur
   ```

3. Для собственной установки укажите в `wrangler.jsonc` свой `account_id` и
   выданный `database_id`. Binding должен остаться `DB`. База и Worker должны
   находиться в выбранном аккаунте Cloudflare.

4. Создайте таблицу сначала локально и проверьте Worker:

   ```bash
   npm run db:local
   npm run dev
   ```

   Откройте `http://localhost:8787`.

5. Создайте таблицу в production D1 и опубликуйте Worker:

   ```bash
   npm run db:remote
   npm run deploy
   ```

   Wrangler покажет адрес вида
   `https://servergrade-results.<account>.workers.dev`.

6. Проверьте выдачу одноразового challenge:

   ```bash
   curl -X POST https://servergrade-results.<account>.workers.dev/api/challenges
   ```

7. После развёртывания официального API обычному пользователю ничего настраивать
   не нужно. Runner уже содержит endpoint
   `https://servergrade.cc/api/results`:

   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/kapybarovv/servergrade/main/servergrade.sh)
   ```

8. Официальный сайт работает на `https://servergrade.cc`. Для своего домена
   откройте Cloudflare Dashboard → **Workers & Pages** →
   **servergrade-results** → **Settings** → **Domains & Routes** → **Add** →
   **Custom Domain** и укажите свой домен. Cloudflare создаст DNS-запись и
   сертификат. Обновите домен в `routes` и публичный адрес в `wrangler.jsonc`,
   затем используйте `https://<your-domain>/api/results`. Для проверки до подключения домена можно
   временно переопределить endpoint только у владельца проекта:

   ```bash
   SERVERGRADE_PUBLISH_URL=https://servergrade-results.<account>.workers.dev/api/results servergrade
   ```

## Модель подтверждения

Runner перед тестом получает `test_id` и одноразовый `nonce` через
`POST /api/challenges`. Challenge действует два часа и привязан HMAC-хэшем к
исходному IP. При публикации Worker проверяет nonce и IP, один раз погашает
challenge и сам считает все четыре оценки только из raw-метрик. Поля score от
клиента игнорируются.

Результаты без корректного challenge принимаются как `unverified` для обратной
совместимости и не должны участвовать в рейтингах. Для подтверждённых запусков
Worker сохраняет ASN, страну, edge-локацию и RTT, полученные Cloudflare на
входящем соединении. Это edge-attestation, а не внешняя проверка полосы: для
последней нужны отдельные probe-серверы.

После записи результат не изменяется и получает серверную HMAC-подпись.
Одноразовый токен загрузки страниц хранится только в виде хэша, действует 10 минут
и удаляется сразу после загрузки заявленного числа страниц. Повторная запись
страницы запрещена.

## Администрирование

На официальном сайте пять быстрых нажатий подряд на переключатель языка
показывают ссылку **Admin**. Вход также доступен по `/admin` и требует пароля.
После входа можно:

- загрузить PNG, JPEG, WebP или MP4 до 750 КиБ, указать ссылку и порядок баннеров;
- включать, скрывать и редактировать баннеры под hero, перед таблицей замеров;
- найти замер по ID, стране, городу или CPU и закрепить его в начале таблицы.

Для собственной установки задайте через `wrangler secret put` два секрета:
`ADMIN_PASSWORD_HASH` — SHA-256 пароля в виде 64 шестнадцатеричных символов,
`ADMIN_SESSION_SECRET` — отдельная случайная строка из 64 шестнадцатеричных символов.
Используйте длинный случайный пароль. Сам пароль и секреты не должны попадать
в Git. Сессия действует 12 часов; запросы изменения данных требуют того же
origin, что указан в `PUBLIC_ORIGIN`.

## Загрузка баннеров

Загруженные файлы баннеров получают адрес `/banners/<id>?v=<sha256>`.
При замене файла версия меняется автоматически; правка названия или ссылки
сохраняет кеш файла. Первое изображение предзагружается с высоким приоритетом,
следующие изображения загружаются по мере прокрутки. MP4 воспроизводится без
звука, по кругу и внутри страницы; при настройке уменьшенного движения видео
приостанавливается. HTML проверяется заново при открытии.

Worker хранит полные файлы в edge-кеше Cloudflare. Перед обращением к нему
проверяются текущая версия и видимость баннера. Существующие изображения
получают версии автоматически, отдельный импорт не требуется. Для MP4
поддерживаются частичные HTTP Range-запросы; в кеш не записываются обрезанные файлы.

Проверка: `npm run test:banner-cache` и `npm run test:admin-client`.

## PNG и предпросмотр ссылок

На странице отчёта доступны отдельные кнопки скачивания PNG и SVG. Готовые
растры хранятся в D1 и выдаются как `image/png` по `/assets/<id>/<page>.png`.
Если у старого отчёта остался только SVG, кнопка PNG преобразует его в браузере.
Worker не выполняет растеризацию при каждом открытии страницы.

Адрес `/test/<id>/preview.png` отдаёт отдельную карточку 1200×630 для
предпросмотра ссылки в Discord, Telegram и X. Пока карточка конкретного замера
не загружена, этот адрес перенаправляет на общую `/preview.png` без кеширования
перенаправления. PNG и карточки можно передать вместе с SVG при публикации;
существующие результаты также допускают привязанный к исходному SVG backfill.

## Индексация страниц

Главная и каждый опубликованный замер получают серверные title, description,
canonical, Open Graph и Twitter Card. Описание замера составляется из его
конфигурации, локации, ASN и оценки; тот же текст виден на странице.
`robots.txt` указывает на `/sitemap.xml`, а индекс sitemap ведёт на страницы
`/sitemap-1.xml`, `/sitemap-2.xml` и далее, по 1000 замеров. Canonical использует
`PUBLIC_ORIGIN`. Админка, API и ошибки получают `noindex`; это не заменяет
аутентификацию админки.

Проверка метаданных: `node --test test/seo.test.mjs`.

## Старый адрес

Конфигурация `legacy/wrangler.jsonc` относится к прежнему аккаунту и его базе.
Worker из `legacy/index.js` перенаправляет страницы на `servergrade.cc`,
сохраняя путь и параметры. Публикации старых runner пересылаются в новый API
с подписанными исходными IP и edge-данными. Прежняя база после переноса
используется этим Worker только для чтения ключа совместимости.

Основной `wrangler.jsonc` относится к аккаунту нового домена. Для развёртывания
используйте соответствующий профиль Wrangler, чтобы не заменить старый
Worker основным приложением или наоборот.
